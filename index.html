Enhancement One

Software Engineering & Design

C++ Client Management System

Refactoring and improving the structure and functionality of a client management application originally developed in CS 410.

Original code ↗Enhanced code ↗Narrative (Word) ↗
Read enhancement narrative

My submission for the Software Design and Engineering category is a client management application written in C++. I created this application in CS 410: Software Reverse Engineering. This application provides an example of an investment company where a user is allowed to view a list of clients or modify the choice of service a client is taking. The two services are brokerage and retirement.

I picked this artifact because it showcases some of my ability to work with C++. It also allowed me to upgrade a previous version of my program using software design skills that I learned later. The old program was able to perform the tasks that were required of it, but it was extremely inefficient due to its heavy use of global variables and hardcoding of client names and choices. It also used multiple if/else if statements to determine which client’s information to modify. Again, this was fine for a small client base, but this would quickly become unwieldy if more features or client selection were added.

I tried to keep my changes from affecting the program's function while still improving its structure. One of the most noticeable changes was the addition of the Client class. Rather than representing choices with global variables, choices are now represented with objects and stored in a collection. With this change, it is easy to define and manipulate a client list, and new clients can be easily added.

I also improved the program by isolating different features into individual methods. This allowed for a better layout and allowed for easier understanding and maintenance. An example of this is the repeated use of if statements to define client choice in the case of service change. The if statement to define client choice is no longer needed. Rather, the service choice can be directly accessed by its index.

The original implementation assumed that the user would input choices in a correct and valid manner. This was not the case in the enhanced version. The enhanced version validates that the user would provide a choice in the correct and allowed range. This was shown by the case where a user choice of 9 was provided to access the main menu. A choice of 5 was provided to select a service, and an incorrect client choice was provided. The program rejected each invalid entry and allowed the user to try again instead of continuing with incorrect input.

This improvement enabled me to make progress toward some of the course outcomes I specified in Module One. It is especially useful for Course Outcomes 3 and 4, as I analyzed an existing solution and updated sections of it with object-oriented programming, a vector collection, modular functions, and input validation. The changes show how to refactor an existing software without affecting its primary purpose.

The enhancement also contributes to Course Outcome 5 by considering how unexpected input can affect a program. Adding validation prevents invalid menu selections, client numbers, and service options from being accepted. My anticipated outcomes did not need to change from my original enhancement plan because the adjustments I made corresponded to the areas I had highlighted for the artifact.

Reflection:

Working on this enhancement showed me how much easier a program can be to maintain when its data and responsibilities are properly arranged. The original program was functional, but having separate variables for each customer resulted in redundant duplication. Using a Client class and a vector shortened the software in several areas while also making it easier to grow.

One problem was ensuring that the improved program performed similarly to the original after undergoing internal structural changes. I evaluated the original application first to establish a baseline, and then I tested the upgraded version by displaying clients, changing their services, and inputting various forms of erroneous input. This helped to ensure that the original functionality was preserved while the additional features operated properly.

Enhancement Two

Algorithms & Data Structures

Android Warehouse Inventory

Expanding a Java inventory application with search, sorting, and inventory-management features.

Original code ↗Enhanced code ↗Narrative (Word) ↗
Read enhancement narrative

I chose my Warehouse Inventory Android application, which I originally designed for CS 360, as the artifact for this enhancement. The application was created to assist users in inventory management by allowing them to add goods with names, SKUs, and quantities. It saves inventory data in a SQLite database and presents the items in a RecyclerView. The original application also allowed users to change amounts, delete things, and receive text notifications when an item approached zero quantity.

This project already had a functional inventory system that could be enhanced by introducing more useful ways to organize and locate data. This made it an appropriate artifact for demonstrating my knowledge of algorithms and data structures.

The artifact provided an excellent chance to change how inventory data is stored and accessed. The first application could display inventory, but there were few options for finding and categorizing specific items.

For the enhancement, I developed a search function that filters products by name or SKU as the user inputs. I've also included sorting options for name, SKU, and amount. The search traverses the inventory list and stores matching results in an ArrayList, whereas the sorting options employ Java Comparator objects.

I also did the search, and sorting functions work well together. A user can filter the inventory while still using the selected sorting method.

This enhancement helped me progress toward the course objective of designing and evaluating computing solutions using algorithmic principles. I utilized data structures and algorithms to solve a practical problem while ensuring the new features integrated seamlessly with the existing application. It also demonstrates my ability to improve a program without compromising its original functionality. My outcome-coverage plan remains largely unchanged, as this enhancement continues to focus primarily on algorithms and data structures.

Reflection:

This enhancement helped me better understand how searching, sorting, and data structures are applied in a real-world context. A key challenge was getting the search and sort functions to work in tandem. Initially, sorting would reload the entire inventory and clear my active search filter. I resolved this by tracking the selected sort option and reapplying it after the inventory was filtered.

Testing the app with various names, SKUs, and quantities also helped me verify that the algorithms functioned correctly.

The artifact I chose is my Grazioso Salvare Animal Shelter assignment from CS 340. The project manages animal shelter data using Python and MongoDB's CRUD capabilities. It also has a dashboard where users may sort animals, see where they are, and look at breed information.

This artifact demonstrates my database experience and how I connected MongoDB to a Python application. I enhanced the CRUD module with better validation, error handling, connection verification, safer update and delete operations, and more flexible searches. I also included sorting and result restrictions in the read operation. These enhancements improved the database code's reliability and ease of use.

This enhancement allowed me to demonstrate my abilities to use programming and database tools to improve an existing software. It also contributed to security by requiring validation and prohibiting empty update or delete queries that could mistakenly affect numerous records. The enhancement contributes to the course results I originally intended for this artifact.

Working on this enhancement taught me the value of making database code dependable and safe, rather than simply having it work. One problem was that I no longer had access to the original virtual environment from CS 340, so I set up a local MongoDB database with test data. I also needed to troubleshoot an issue with my advanced search query.
